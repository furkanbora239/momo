- Symptom: `task(category=...)` sessions die ~6 ms after creation (`prompt_async failed`, `Die(UnknownError)`); agent-level text: `Agent "Sisyphus-Junior" not found. Make sure the agent is registered`.
- Root cause: v1 roster slimming put `sisyphus-junior` into `V1_DISABLED_AGENTS_DEFAULT` (`packages/omo-opencode/src/config/validate.ts`) — but Sisyphus-Junior is the agent the category executor spawns. Categories open, worker closed.

- Verification: delegate-task + config suites green; live category probe post-restart.

### F2 — task(model=...) ignored on named-agent (`subagent_type`) delegations
- Symptom: `task(subagent_type="general", model="neuralwatt/glm-5.2")` resolved `opencode-go/glm-5.2`; the category path honored the same param.
- Root cause: `packages/omo-opencode/src/tools/delegate-task/subagent-resolver.ts` resolved models only via the agent's own chain; explicit param consulted nowhere except the advisor gate.
- Fix: normalized `args.model` wins over the default chain in `resolveSubagentExecution` (advisor binding keeps precedence). Test: `subagent-explicit-model.test.ts`.
- Architecture note: mechanical backbone of "orchestrator decides models" — catalog_pick at runtime, then task(model=...) routes there.

### F3 — Provider-bias routing (static lists + hardcoded neuralwatt-first chains)
- Symptom: everything routed to opencode-go (user config `models` lists headed by it; a since-reverted wave also prepended neuralwatt rungs in code).
- Decision (user, 2026-09-02): NO static provider preference anywhere. The orchestrator picks models at runtime via the catalog (`catalog_pick`), chains stay provider-neutral availability fallbacks.
- Fix: all `agents.*.models` / `categories.*.models` lists deleted from `~/.omo/omo.jsonc`; neuralwatt chain prepends reverted (6 files back to HEAD); `catalog.prefer_providers` default `[]` (key remains, opt-in only).
- Kept on purpose: chain fallthrough when a head model is unavailable (gate fix, provider-neutral).
