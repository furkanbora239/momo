## Phase 2 - tool surface / permissions (P1)
4. **M2a**: re-derive `launchTools` / `getAgentToolRestrictions` against V2 semantics - V1 prompt `tools` deprecated -> session-level permissions (deny removes the tool from the surface); apply renames bash->shell, task->subagent, write/patch->edit. While re-deriving, define the worker baseline read-side surface (codegraph search/context/explore, skill access, websearch/webfetch) as part of the execution-agent allow-set - the M1d QA worker had NO skill tool and no codegraph and had to shell around it (evidence: `momo_nots.md` 8.1). Files: `src/shared/session-tools-store.ts`, `src/shared/permission-compat.ts`, delegate-task engine call sites.
5. **M2b**: per-agent permission maps for the kept roster; sandbox assert the child tool surface equals the expected set - and that a worker's expected set POSITIVELY includes codegraph, websearch/webfetch and skill access (assert presence, not only absence).
6. **M2c - tool-call pathway spec (deliverable for the PROMPTS the user writes themselves)**: per-agent allowed tool names under V2 naming, prompt snippets referencing `shell`/`subagent`/`edit` (never bash/task/write), permission frontmatter examples for the native markdown agents of Phase 3. This is the ONLY prompt-content item in this plan.
7. **M2d - question routing (worker -> orchestrator)**: subagent `question` calls surface only to the end user today (evidence: `momo_nots.md` 8.2); add a routing target on the question path (`orchestrator` default | `user` explicit escalation), stream pending questions to the orchestrator as an event, answer via `task(task_id=..., answer)`, fall back to the user after a bounded wait. Sandbox assert: a child question reaches the orchestrator first and is answered without touching the user. (Behavior item, no prompt content - M2c stays the only prompt deliverable.)

## Phase 3 - native markdown agents (decision D3)
8. **M3a**: author `.opencode/agents/*.md` for the kept roster (worker, explore, librarian, research, planner, executor, reviewer, advisor, catalog-researcher): frontmatter description/mode/permissions, NO model field (preserve `/models` inheritance); variant routing stays engine-side (`sisyphus-agent-factory` resolves from session model).
9. **M3b**: plugin stops registering overlapping agents (keep only engine-coupled ones: advisor gate, catalog-researcher); ship markdown agents via npm `files` like skills.
10. **M3c**: sandbox QA - agents appear in the native panel, permissions enforced, no model pinned, session-model inheritance intact.

## Phase 4 - cleanup & closure
11. **M4 (D1 legacy quarantine)**: move v1-dead parts to `src/legacy/` with a banner README (retained-not-deleted, known-dead-under-v2); no imports from live code; typecheck green; includes the dead `sessionGoneTimeoutMs` fixture field cleanup.
12. **M5 (D2)**: retire the `/tasks` panel (native Alt agents panel takes over); keep `/pool` and `/provider`; TUI toasts via `@opencode/plugin/tui`; update tests.
13. **M6 bridge sweep** (one item at a time, grep+test evidence each): system override -> `ctx.session.hook("context")`; map `session.execution.interrupted` in event-hook-bridge; parent-wake fix; live-server-route; prompt-async-gate holdMs anomaly (~3.3s vs 15000); `session.todo` mapping.
14. **M7 standing QA infra**: sandbox provider cache seed (fixes the empty-child P3), `--self-test` driver script wrapping the M1d pattern, standing regression exam (5-parallel survive + tool surface + no verdict-noise regressions).
15. **M8 closure**: update `PROJECT_STATE.md` + `AGENTS.md` recent-updates + PR body; open PR `fix/opencode-v2-plugin-migration` -> `dev` with the gate numbers from the status md.

Ordering: 1->3 strictly first; 4-7 next; 8-10 after M2c (frontmatter permissions come from it); 11-15 last.
