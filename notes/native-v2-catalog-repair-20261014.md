# Native v2 selected-model maintenance and policy repair

The first Anchor run created research while merely viewing unknown model candidates. With 53 models, this produced 53 headless tasks and stranded caller choices. Catalog snapshots now keep unknown facts visible and create no research. Only an actual dispatched unknown model enters a durable per-project queue.

Research requires the explicit `[opencode].catalog.research_executor` object with `providerID` and `modelID`. An absent binding is visible as `paused/executor_unbound`. The bound researcher is checked against live catalog availability, tools, pool and native role eligibility, and uses the existing task engine without Jev selection or fallback. A single maintenance assignment waits while ordinary tasks or their root session are active, including a foreground task awaiting caller selection. Maintenance completion does not deliver a root result, and a native question fails and interrupts the headless assignment.

Queue identities include the project queue path, source root and exact model. Restart resumes the same interrupted task only through the idle queue; the engine also checks the current native root activity before dispatching a persisted queued maintenance job. Completed research is not rerun. A reserved launch with no corresponding task stays `paused/research_launch_uncertain` and is not recreated automatically. That uncertain entry does not block another selected model. A failed research job remains visibly failed rather than silently launching another model.

Native provider errors explicitly identifying training on request data and privacy settings quarantine the actual model for one hour in its project. Other models from the same provider stay available. The task engine accepts this observation only after event identity/sequence/state guards and task persistence, before another queued task can dispatch. Durable native assistant-message identities and originating model checks prevent old replay from extending expiry or quarantining a replacement model. Native completion time anchors the expiry when present; without it, the first accepted observation anchors expiry, and the same native message cannot renew it. Delayed older native failures cannot shorten a newer quarantine. A transient native failure-inspection error is persisted separately from the actual task failure. An accepted privacy failure also stays pending while native active-session bookkeeping still reports running or immutable failure identity is unavailable; event text alone never quarantines a model. Non-privacy failures do not enter that wait. Only that exact model waits for the existing watchdog to retry inspection; other models can continue recovery. No provider settings or privacy consent is changed.

## F18: routing-pending capacity bypass

The live regression fixture exposed a separate dispatch race on 2026-10-17. A new task was persisted as `queued` with `routeStatus: pending` before its Jev call completed. An unrelated queue pump could select that task while its model was still absent, then wait for its routing lock and start it after model assignment without checking the selected model capacity again. The diagnostic built-bundle trace showed the second m1 candidate with no model, the first m1 worker already running, and the configured m1 concurrency limit equal to one. This is a confirmed capacity bypass; it is not evidence that it caused the original Anchor resource crash.

The pump now excludes pending routes and reloads repository state inside the dispatch lock before checking current capacity and unresolved failures for the actual model. It does not hold a global lock across Jev. A held-route behavioral regression fails before the fix and passes after it. The rebuilt uninstrumented plugin also passed the actual native two-assignment fixture: one m1 HTTP, no second m1 session, successful independent m3 execution, and caller selection for the invalidated second assignment.
