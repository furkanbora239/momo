# Native v2 result consumption repair

This slice addresses F03, F07 and F15 from the first Anchor native v2 live test.

A successful synthetic-message API call now records admission, not consumption. Version 2 durable receipts become delivered only after native `session.inbox.delivered` or authoritative message lookup. Stable message IDs are persisted before admission; missing delivery inspection and lost SSE events recover without rerunning completed child work. Legacy receipts claiming delivery are rechecked on restart. Unknown message lookup failures retain the receipt for retry rather than treating arbitrary error prose as absence.

Root result and question notifications use native steer so busy generations can observe them between steps. On OpenCode 2.0.28, queue/resume=true drains after the current generation finishes; the baseline proof does not claim that such entries always remain queued forever. Answering a forwarded native form preserves its fields, forwards the answer to the same child session, and retracts pending notification/forms; late callbacks cannot overwrite the accepted answer.

Department children queue individual results without waking their coordinator. Once children finish, the engine durably stores aggregate provenance and binds child receipts to one stable aggregate ID before native mutation. It retracts individual pending entries and sends one native aggregate. Both original child results remain stored, and one aggregate-consumed event acknowledges every bound child. Restart after individual retraction or after consumed admission with a lost response recovers the same batch without duplicate worker execution. Cancellation of the coordinator prevents pending aggregate reactivation.

The integrated proof includes two actual child cancellations producing one department generation. Restart SSE disconnections are caught and reconnect, and both proof processes exit 0. See [`notes/qa/native-consumption-repair-20261016.json`](qa/native-consumption-repair-20261016.json) for source hashes and sanitized receipts. Real native QA uses the installed OpenCode binary, an actual built momo plugin, local-only mock model/Jev endpoints, isolated HOME/OPENCODE_TEST_HOME/all XDG directories, explicit process-group cleanup and read-only before/after counts of the real user's three session tables. The separate contract mode exercises SDK behavior and is not presented as an integrated plugin test.

Limitations: delivery proves native context consumption, not correctness or acceptance of a worker's result. It does not reconstruct the original private Anchor session or alter its existing inbox. The API compression and catalog/accounting fixes are separate slices.
