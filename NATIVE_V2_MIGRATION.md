# OpenCode v2 native migration

The native runtime is an OpenCode v2-only surface. It uses the v2 provider, model, integration, session, permission, and TUI APIs directly; the V1 client/config adapters are not part of this path. Native role visibility remains owned by OpenCode.

The two-tool contract is `momo_task` for task work and `momo_consult` for consultations. `momo_task` exposes create, resume, select, answer, cancel, status, and wait. `momo_consult` exposes start, select, status, and wait; consultation requests are recorded with kind `consultation`. Callers do not supply a role or session identity: the runtime derives the caller from its server context and scopes status/wait operations to the root lineage. A route may return a selected model, an `awaiting_selection` response with candidates, or `unavailable`. Selection revalidates the current provider/model state, hard-allow pool, role rules, and caller ownership without invoking Jev again. Invalid input and authorization failures are surfaced as clear errors; router or Jev unavailability becomes a persisted manager-visible result instead of an implicit model fallback.

At the root, `orchestrator` may route directly to a worker or use `planner`, `executor`, or `reviewer` as a department lead. Department children are worker roles. Worker roles can request consultation but cannot delegate. `advisor` can only handle consultation and cannot delegate or consult. The advisor model pool is the project `.omo/omo.jsonc` setting `[opencode].manager.advisor_models`, with the existing momo config layering rules. It is intersected with the general model pool. An empty advisor pool disables consultation. The `/advisor-pool` TUI panel edits that setting; `/pool` controls the general hard-allow model pool and `/providers` controls provider availability. An empty general pool means all models are allowed; it does not disable task routing.

The Jev router sees the full task brief and all currently eligible connected candidates, including unknown price and capability fields as unknown. It must not substitute an unverified free price or ability. Missing model knowledge queues an injected background research hook and never blocks dispatch; requests are deduplicated per model during the router lifetime. The native `momo_catalog_enrich` tool accepts only source-backed HTTP(S) profiles and requires both the exact runtime agent ID `momo-catalog-researcher` and a baseline-owned agent check, excluding user agents that reuse the name. Research profiles stay separate from runtime outcomes. Low confidence, Jev failure, malformed answers, exhausted budget, or circuit-breaker state returns caller options; no other model is silently chosen. A versioned JSONL ledger retains the request, candidate snapshots, Jev response/probabilities or failure evidence, caller selection, actual runtime dispatch, and runtime outcome. Outcomes are based on task runtime state; verification stays `unknown` unless runtime evidence supports a stronger label.

The pinned Codebase Memory MCP candidate remains disabled by default. Fixture QA found that source changes were not visible until a full manual reindex (`automaticFreshness: false`), so its search results are not safe as a default source of truth. The pinned binary, cache, and runtime stay under managed task-specific roots; no installer or global MCP configuration is used. A source-level native fallback registrar now builds v2 MCP configs for bundled LSP and ast-grep servers and exports role allowlists; its tests verify the actual MCP `tools/list` names and keep rename/rewrite away from department coordinators. Baseline runtime registration, tool execute guards, and a real-TUI proof remain pending, so the fallback is not yet claimed as an integrated working role surface.

Verification status: 48 focused tests across eight files (161 assertions), the native-search release fixture, and full monorepo typecheck passed in the isolated integration worktree. The TUI setup uses the root-scoped read-only catalog snapshot RPC for `/pool` and `/providers`; advisor-pool persistence is wired by the baseline through project JSONC. A private-socket tmux retry did not render the plugin controls, so no live TUI or task-engine proof is claimed. No paid model was used; the integrated fake-provider TUI and task harness remains a release gate.
